## الاختبارات المنفذة

- 289 اختبارًا آليًا: 119 CJS و170 MJS، دون فشل؛ بناء إنتاج ناجح، وفحوص GitHub الخاصة بالأمان والواجهة وفحص الأسرار ناجحة.
- 19 اختبار خلفية حيًا بأربعة أدوار اختبار وMFA فعلي.
- 21 اختبارًا للدومين الرسمي، جميعها ناجحة بعد الإصلاح.
- 7 اختبارات إضافية للخروج من جميع الأجهزة والجلسة المحمية والعمليات الحساسة. جرى التحقق صراحةً من اسم عملية الإيداع الفعلية `deposit.submit`.
- اختبار SQL متراجع عنه للتوثيق والمحفظة والدور والمستند والتدقيق والتجميع والحذف بعد 30 يومًا.
- ثبّت اختبار الإنتاج أن `redirect:error` غير مدعوم في Workers. استُبدل بـ`manual` مع رفض كل 3xx دون تمرير بيانات الاعتماد لوجهة أخرى. الاختبارات المحلية وحدها لم تكن إثباتًا لهذا المسار، ولذلك أُعيد اختبار الدومين حتى نجح.

التفاصيل الآمنة القابلة للمراجعة في `security-acceptance-results-20261025.json`. لا يحتوي الملف على مفاتيح أو JWT أو كلمات مرور أو IP شخصي أو إحداثيات حقيقية.

## الحسابات والبيانات

استُخدمت أربعة حسابات معزولة مع أرصدة صفرية. بعد الاختبار أُلغيت جميع جلساتها ومفاتيحها، وأوقفت الحسابات وخُفضت أدوارها إلى customer وحُظر دخول Auth إليها؛ لا جلسة أو مفتاح أو دور إداري اختباري نشط. أبقيت سجلاتها للمراجعة بدل حذف تاريخ الاختبار. مُسحت إحداثياتها الاختبارية، وحُذفت ملفات بيانات اعتماد الاختبار المحلية بعد إقفالها.

أرصدة العملاء الحقيقيين مطابقة لبصمتها قبل العمل: `c095207b16374eeda89edcd787edf925`. لم تنشئ حسابات الاختبار أي طلب أو إيداع أو قيد محفظة. لم تُنفذ هذه المهمة كتابة على المنتجات أو الأسعار أو العملات؛ تغيرت بصمة الكتالوج أثناء فترة التشغيل وظهرت إضافة منتج خارج أعمال الأمان، لذلك لا يُدعى ثبات جميع أسعار الإنتاج خلال الفترة ولا تُعاد أسعار تلقائيًا اعتمادًا على هذا التقرير.

## حدود الإثبات والمتبقي

- لا يزال فحص أدوات الإدارة بصريًا داخل جلسة متصفح مدير مخول، وكذلك الاختبار البصري الفعلي للهاتف، غير مكتمل. اختبارات DOM وAPI لا تُسمى اختبارًا بصريًا حيًا. تعليمات المتصفح تتطلب نموذج browserAuth الآمن للدخول؛ لا يُطلب إرسال كلمة المرور في المحادثة ولا تُحقن جلسة لتجاوز الدخول.
- لا GPS دون موافقة منفصلة، ولا تجاوز لأذونات الجهاز. بيانات IP تقريبية ومتأثرة بالشبكات المشتركة وVPN؛ الموديل واسم الجهاز المبلغ عنه لا يثبتان هوية المالك.
- رصد فشل الدخول يغطي بوابة الموقع؛ الاتصالات المباشرة إلى Supabase Auth ومسار SDK الاحتياطي أثناء أعطال البنية يخضعان لحماية وسجلات Supabase ولا يُدعى أن لوحة التنبيهات تجمع كل محاولاتهما.
- لم يُنفذ شراء أو إيداع بأموال حقيقية أو طلب عند مورد حقيقي لأغراض هذا الاختبار. إثبات عدم تعطلها هنا هو اختبارات التراجع والحمايات وعدم كتابة مال، وليس ادعاء تنفيذ عملية مالية ناجحة جديدة.
- مهمة الحذف كانت تعمل بنجاح قبل التوسعة، وأوامرها الموسعة اختُبرت بمعاملة متراجعة؛ لم يُنتظر التشغيل المجدول التالي عند 03:00 UTC لإعلانه ناجحًا مسبقًا.

## الرجوع عند الحاجة
