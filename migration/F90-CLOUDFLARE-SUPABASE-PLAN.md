# F90 CARD — خطة النقل إلى خدمات مجانية (مرحلة التحضير)

**التاريخ:** 2026-10-18  
**الفرع المنفصل:** `migration/cloudflare-supabase-20261018`  
**الحالة:** تحضير فقط؛ لا تغيير على `main` أو `www.f90card.online`.  
**قاعدة أساسية:** لا تُحذف البيانات أو تُحوّل سجلات DNS أو تُغيّر بيانات إنتاج قبل فحص النسخة الجديدة وتأكيد صاحب المتجر.

## البنية المستهدفة
- **Cloudflare Pages (حساب جديد):** واجهة الموقع ولوحة الإدارة والصور العامة الثابتة. Git integration من مستودع GitHub الحالي، دون إنشاء حساب GitHub جديد.
- **Cloudflare Workers (الحساب الجديد نفسه):** مهام خفيفة مجدولة، تخزين مؤقت لكتالوج عام، وربط مدروس للعمليات فقط عند الحاجة. تجنب الاعتماد على الحصة في مسار خصم الرصيد دون آليات فشل آمنة.
- **Supabase (حساب جديد):** الهوية والمستخدمون، بيانات المعاملات، الأرصدة، الإيداعات، RLS، الـ SQL functions، الشحن، التخزين الخاص.
- **GitHub الحالي:** كود المشروع مع الاحتفاظ بالتعديلات الجارية. تحديث فرع النقل بآخر نسخة من `main` قبيل الإطلاق.
- **Vercel القديم:** يظل بلا تغيير حتى تمام التحويل؛ يُرفع الاعتماد عليه بعد التأكد من كل شيء.

## نتائج جرد أولي حيّ (الأعداد تتغير مع استمرار العمل)
- مخطط `public`: 34 جدولًا، ~50 دالة SQL، 15 Trigger.
- Auth: 19 مستخدمًا عند الجرد الأخير. هذا العدد ديناميكي.
- Storage: 702 ملفًا، نحو 1.19 GB (بضمنها نحو 626 MB صور و444 MB راديو).
- تطبيق الواجهة يستخدم Supabase URL القديم في `config.js` و`index.html`.
- الوظائف الخلفية: 7 Edge Functions؛ الرئيسية `f90-platform` مرتبطة بطلبات التاجر والمورد.
- نحو 373 عنوانًا محفوظًا في صور المنتجات/الأقسام/البنرات يشير إلى Storage القديم.
- ملفات الراديو الحالية فيها مواد أكبر من حد 25 MiB لملفات Cloudflare Pages. لا ننقل الراديو القديم بكامله.

## متطلبات المنتجات (ثوابت إدارية وبيانات مورّد)
1. اسم الخدمة العربية يُعرض مطابقًا لاسم المورد الأصلي.
2. الصورة الأصلية تُحمّل وتُنشر مرة واحدة، ثم لا تُستبدل تلقائيًا؛ التغيير لاحقًا من لوحة الإدارة يدويًا.
3. ترتيب الخدمات والأقسام يُحفظ تمامًا مع استمرار السحب والتحكم اليدوي.
4. الحدود الدنيا/العليا تبقى بنفس طريقة العمل الحالية، مع التحقق النهائي عند إرسال الشحن.
5. سعر البيع اليدوي محفوظ حتى يُفعّل المدير صراحة خيار «المزامنة مع سعر المورد».
6. تكلفة المورد الحية تحفظ منفصلة عن التكلفة اليدوية المعتمدة عند وجود Override.
7. هامش ربح عام/قسم/منتج، وزر مزامنة أسعار مع تنبيه الخسارة، بلا الكتابة على الأسعار اليدوية.
8. توافر الخدمة وحالة التعبئة وتقدم الطلب تُزامن تلقائيًا مع ياسين كارد.
9. الشحن اليدوي والتلقائي كلاهما يجب أن ينجح، مع منع إرسال مكرر (idempotency) وفحص تسجيل الأحداث.

## الراديو
حذف واجهة وأقسام الراديو القديمة، والإبقاء على أغنية واحدة مختارة ومرخّصة، مع زر تشغيل اختياري بدون autoplay أو polling. عدم نقل المقاطع القديمة بلا حاجة.

## بوابات السلامة
- **قبل الترحيل:** نسخ احتياطي مستقل مشفر، جرد المخطط + بيانات Auth المشفّرة والأدوار والسياسات والـ Storage وأسماء ملفات الوظائف؛ اختبار استعادة النسخة.
- **في البيئة الجديدة:** استيراد Auth مع معرفات المستخدمين، حسابات Google/البريد، RLS وسياسات Storage، وظائف الخلفية، أسرار الخادم عبر إعدادات آمنة فقط.
- **الاختبارات:** تسجيل الدخول لكافة الطرق؛ فتح لوحة الإدارة؛ تصنيف وترتيب المنتجات؛ دفع وإيداع وحركات محفظة؛ تأكيد السعر والتوافر، الشحن اليدوي والتلقائي دون إرسال طلب حقيقي مدفوع أثناء الاختبار، رسائل البريد، API التجار، صور المنتجات.
- **المطابقة:** معرفات Auth والتراخيص، عدد السجلات، كل رصيد مع سجل المحفظة، الطلبات والإيداعات وحالاتها، إعدادات المورد، الأسعار اليدوية، الروابط المصورة.
- **القطع النهائي:** إيقاف إنشاء عمليات مالية جديدة لفترة صيانة محدودة، مزامنة الفروقات من المصدر القديم، إعادة اختبار خصم الرصيد/الطلب، مراجعة DNS **بما فيه MX/SPF/DKIM**، تحويل الدومين بعد اعتماد المالك.
- **ما بعد النقل:** مراقبة الإخفاقات والحصة والحزم المجانية وعدم تعطيل القديم إلا بعد ثبوت عدم وجود أي اعتماد.

## معوّقات يجب حلها قبل التشغيل
- الحسابان الجديدان (Cloudflare وSupabase) لم يربطا بعد ولم توضع فيهما مشاريع.
- لا ضمان لاستخدام مجاني غير محدود: يوجد سقف لكل خدمة، وإيقاف بعض الوظائف الثانوية لا يحافظ تلقائيًا على توفر المصادقة والمدفوعات.
- يجب إدارة صور الرفع الإداري في نظام ثابت واضح يسمح بالتغيير اليدوي دون تجاوز حد 25 MiB للملف على Pages.
- لا بد من منع تضارب العمليات المالية، اختبار إعادة المحاولة للمورد، وعدم تكرار الطلبات.
- يجب إعداد مسار نسخ احتياطي دوري مستقل بما أن الخطة المجانية لا تتضمن نسخًا تلقائية كاملة.
- عند الهجرة قد تنتهي جلسات العملاء الحالية ويلزمهم إعادة تسجيل الدخول مع الحفاظ على حساباتهم وكلمات المرور المشفرة بعد نقل Auth بنجاح.
