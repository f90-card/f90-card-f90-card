# دليل النقل الآمن من الهاتف فقط | F90 CARD

## شو جهّزنا؟
ملف التشغيل `.github/workflows/f90-db-preflight.yml` على فرع النقل، وهو **فحص فقط**.
لا ينقل مستخدمين أو كلمات مرور أو أرصدة. ولا يرفع قاعدة البيانات إلى GitHub أو يطبع إيميلات العملاء أو كلمات المرور. يتحقق من اتصال القاعدتين ويقرأ أعداد السجلات، ويجرب إمكانية تصدير Auth إلى `/dev/null` دون حفظها.

الفرع: `migration/cloudflare-supabase-20261018`.

**تنبيه:** GitHub لا يُظهر زر `Run workflow` لملف `workflow_dispatch` موجود على فرع جانبي فقط؛ لازم يكون الملف بالفرع الافتراضي للمستودع لتفعيله. لا تنقل الملف إلى `main` في مستودع الإنتاج تلقائيًا، لأن ذلك قد يحفز نشر Vercel. الخيار المفضل هو مشروع GitHub خاص مستقل للنقل **على نفس حسابك الحالي**، ثم يوضع الـWorkflow في `main` هناك عند جاهزية التنفيذ. هذا لا يعني إنشاء حساب GitHub جديد.

## إعداد مصدرَي الاتصال (داخل GitHub فقط، من الهاتف)
السرّان المطلوبان:
- `F90_SOURCE_DATABASE_URL`: رابط اتصال Postgres الكامل من مشروع Supabase القديم (`xzqnrpycjxfbyrfaolud`).
- `F90_TARGET_DATABASE_URL`: رابط اتصال Postgres الكامل من المشروع الجديد (`ogkipkavlywgwhtomoca`).

من مشروع Supabase اضغط `Connect` > `Session pooler` (port 5432) ثم انسخ رابط الاتصال، وضع كلمة مرور **قاعدة البيانات** في مكان `[YOUR-PASSWORD]`. إذا احتوت كلمة المرور على رموز خاصة فيجب ترميزها داخل رابط URI؛ والأفضل استخدام كلمة مرور مولّدة آمنة يسهل ترميزها. إذا لم تتذكر كلمة المرور، استعمل تغيير/إعادة ضبط كلمة مرور **قاعدة البيانات** من إعدادات المشروع بحذر لأنها قد تؤثر على أي اتصال قائم؛ لا تغيّر كلمة مرور قاعدة الإنتاج دون تدقيق اعتماداته.

في GitHub: `Repository > Settings > Secrets and variables > Actions > New repository secret`، واكتب اسم السرّ ثم قيمة رابط الاتصال داخل حقل Value. لا تضعه أبدًا في الملفات، Issues، رسائل الدردشة أو workflow inputs.

- قد يفضل إعداد مستودع **خاص** للترحيل وتقييد الصلاحيات بدل المستودع العام الحالي.
- لا ترسل لنا أي رابط اتصال، كلمة مرور، Access token أو صور شاشة تظهر قيمها. بعد حفظ السرّين لا يمكن قراءتهما علنًا من GitHub.
- إذا جرى تعريض كلمة مرور في سجل التشغيل، يجب تدويرها فورًا وفحص السجلات.

## إجراء التشغيل عند تفعيل workflow بأمان
`Repository > Actions > F90 - Read-only Database Migration Preflight > Run workflow`.
اترك الناتج كما هو؛ الأعداد فقط كافية لتأكيد نجاح الاتصال. لا تشغّل استيراد Auth أو أموال أو تغييرات DNS عبر هذا الملف.

## مرحلة النقل الفعلي اللاحقة (لم تنفّذ بعد)
1. إصدار **نسخة احتياطية مشفّرة مستقلة** من الإنتاج.
2. إعداد استعادة كاملة Auth تشمل المستخدمين وكلمات المرور المشفّرة وهويات Google، معالجة السجلات الثلاثة الجزئية في المشروع الجديد بأمان.
3. نقل بيانات المحافظ والطلبات والإيداعات والدفتر المالي، والسياسات والدوال والـTriggers؛ مراجعة البيانات بدقة.
4. نقل ملفات الصور العامة إلى استضافة ثابتة، والوثائق الخاصة إلى تخزين خاص، وإعادة إعداد OAuth والبريد ووظائف Supabase.
5. إجراء فحوص الفروقات ثم إيقاف الكتابات المالية أثناء القطع النهائي، وعدم إعادة تفعيل أي مورد قبل ضبط منع تكرار الطلبات.
6. تحويل DNS إلى Cloudflare **بعد موافقة صريحة واختبارات مكتملة**. لا تغير الدومين حاليًا.
