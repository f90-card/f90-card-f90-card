# F90 CARD — نتيجة API التجار
تحديث التحقق: 21 أكتوبر 2026 بتوقيت القدس.

**API الرسمي منشور ومختبر. بقيت صور ثمانية منتجات معطلة غير محسومة الهوية؛ لا يُعلن اكتمال أعمال الصور بالكامل.**

## العنوان وطريقة الربط
- API: https://www.f90card.online/api/v1
- الدليل: https://www.f90card.online/#/api-guide
- إصدار المفتاح: https://www.f90card.online/#/developers
- يتطلب إصدار المفتاح حساب تاجر نشطًا وموثّقًا. ينسخ السر عند إنشائه فقط؛ إصدار بديل يلغي المفتاح السابق.
- المصادقة: ترويسة x-f90-key من خادم التاجر. العمليات POST بصيغة JSON؛ GET لتعريف الواجهة فقط.
- الصلاحيات التي يفرضها الخادم: catalog وbalance وorders.
- /api/merchant باقٍ للتوافق. لا يُرسل مفتاح المورد أو service_role إلى التاجر.
- العمليات المراجعة: categories, services, service, balance, quote, checkout, add, status, history.
- profile وcheck وwebhooks ليست جزءًا من العقد المنشور. لا يُفترض توافق متجر يطلب بروتوكولًا آخر تلقائيًا.

## الإصلاحات المنفذة
1. إضافة Pages Function فعلية للمسار /api/v1، مع إبقاء المسار السابق.
2. إزالة Supabase القديم من مثال خادم التاجر، وتوحيد عنوان الربط في الدليل وإنشاء المفتاح واختبار الاتصال.
3. دليل عربي بعنوان «دليل التاجر وربط المتاجر»، مع شرح المعرفات الثابتة والحقول ووحدة التسعير والحدود والرصيد وحالات الطلب.
4. إظهار الخدمات اليدوية المؤهلة التي كان فلتر الكتالوج يستبعدها لعدم ارتباطها بمورد.
5. فرض رفض البيانات المختلفة لمرجع الشراء نفسه داخل قفل المحفظة في قاعدة البيانات:
   supabase/migrations/20261020165635_merchant_checkout_idempotency_conflict.sql
6. استرجاع الطلب السابق قبل فحص توفر المورد الحالي؛ منع حالة المورد من حجب استرجاع طلب مدفوع.
7. إرجاع F90_NOT_FOUND / 404 بدل PGRST116 للطلب غير الموجود أو غير المملوك.
8. رسائل عربية واضحة للمفتاح غير الصحيح والصلاحية المفقودة مع الحفاظ على الأكواد.
9. تصحيح اختبار صفحة الإدارة: /admin.html يحوّل 308 إلى /admin على النطاق نفسه، وهو السلوك الطبيعي. طلبات API لا تتبع التحويلات مع المفتاح.
10. الحفاظ على أحدث تصميم الشراء والإجمالي الرقمي؛ لم تُسترجع نسخة checkout قديمة.

### HTTP حي بمفتاح تجريبي صحيح
نجحت services وcategories وbalance وquote. رُفض المفتاح الخاطئ والملغى 401، والصلاحية المفقودة ومحاولة الإدارة 403، والرصيد غير الكافي 402. الطلب غير الموجود يعيد 404 / F90_NOT_FOUND.
في لقطة القبول الأولى كانت النتيجة 567 خدمة و92 قسمًا؛ هذه لقطة زمنية وليست عددًا ثابتًا. لم يظهر تكرار service أو سعر مفقود/غير موجب، ولم تظهر حقول مفاتيح الموردين أو endpoint أو service_role في كتالوج الفحص.
سجل الاستخدام الفعلي في آخر ست ساعات من فحص المتابعة أظهر 7 طلبات services و4 طلبات balance ناجحة بحالة 200.

### اختبارات SQL بمعاملة تُلغى بالكامل
استخدمت الدوال المالية الحقيقية مع هوية ومنتج مؤقتين غير مرئيين للجلسات الأخرى:
- السعر من الخادم ورفض اختلاف الإجمالي والحقول الناقصة.
- طلب واحد وخصم واحد وحجز مخزون واحد عند تكرار المرجع.
- رفض المرجع نفسه مع بيانات مستلم مختلفة.
- استرداد واحد واستعادة مخزون واحدة عند تكرار فشل الطلب.
- رفض الرصيد غير الكافي.
لم يُستدعَ المورد ولم تُحفظ طلبات الاختبار أو قيودها المالية.

أُزيل الحسابان التقنيان ومفاتيحهما بعد التأكد أن الرصيد صفر ولا طلبات أو قيود مالية. في الفحص الحالي لا توجد حسابات الاختبار المذكورة. عدد مفاتيح التجار الحالي 16، منها واحد نشط؛ لم تُعد هذه المهمة تفعيل المفاتيح الملغاة أو تعديل مفتاح العميل الموجود.

### فحص المتصفح
- /api/v1 يعرض JSON الصحيح.
- الصفحة الرئيسية تُحمّل واجهة المتجر والكتالوج.
- /admin.html يتحول إلى /admin ويعرض نموذج دخول الإدارة.
- لا يُدّعى تسجيل دخول إداري أو شراء/إيداع حقيقي بالمتصفح في هذه الجلسة.
- تعذر TinyFish المدفوع سابقًا لنفاد الرصيد، ثم أُنجز فحص الصفحات العامة بالمتصفح المتاح دون شراء رصيد.

## سلامة البيانات وحدود النتيجة
- Supabase الحي: ogkipkavlywgwhtomoca؛ f90-platform إصدار 25 عند التحقق.
- لم يُعدّل مشروع وكالة مجلس القمة، ولم تُحذف طلبات تاريخية أو يُستعمل مال العملاء.
- لم يتغير إعداد المورد أو إعداد العملات بهذه المهمة. مزامنة ياسين الموجودة استمرت.
- البصمة العامة للأسعار تغيرت أثناء العمل المتزامن على المتجر؛ لذلك لا أزعم تجمد جميع الأسعار طوال الجلسة. هذه المهمة لم تُصدر تحديث أسعار أو تعِد أسعارًا قديمة.
- صاحب المتجر أعفى صراحةً شرط النسخة الاحتياطية. لم تُنشأ نسخة احتياطية.
- لم تُنفذ شحنة مدفوعة فعلية لدى ياسين؛ اختبارات adapter والمنطق المالي المعزولة لا تعادل شحنة خارجية.
- لم يُربط برنامج متجر تجاري خارجي محدد؛ اختُبر عميل HTTP خادمي تجريبي والعقد المنشور.
- التحذيرات الأمنية السابقة في Supabase ليست شهادة فشل للاختبارات أعلاه ولا شهادة خلو شاملة من الثغرات.
- المنتجات الثمانية المتبقية بلا صورة معطلة: WWWW وzzzz وKkkkk وGgggg وريد باكيج 10000 وريد باكيج 3000 وتسليم رواتب عبر إي باي وZain TV. تحتاج مطابقة هوية موثوقة، ولم توضع صور تخمينية.
- يوجد ارتباط مورد مكرر لنسخة إكزينا نشطة وأخرى معطلة؛ لم تُحذف أي نسخة، ولا ظهر تكرار service في API المفحوص.

## نص جاهز للتاجر
اربط خادم متجرك على:
https://www.f90card.online/api/v1

أرسل POST وJSON بالترويستين:
Content-Type: application/json
x-f90-key: مفتاحك_الخاص

ابدأ بالقراءة:
{"action":"services"}
{"action":"categories"}
{"action":"balance"}

احفظ service معرّفًا ثابتًا، وحدّث المنتج نفسه عند المزامنة. استخدم حقول الشحن والكمية وunit_quantity كما تعيدها الخدمة. قبل الشراء اطلب:
{"action":"quote","product_id":"معرف_الخدمة","quantity":1000}

ثم:
{"action":"checkout","product_id":"معرف_الخدمة","quantity":1000,"fields":{"account_id":"معرف_المستلم"},"idempotency_key":"مرجع_فريد_محفوظ_قبل_الإرسال","expected_total_usd":الإجمالي_المعاد_من_quote}

fields تختلف بحسب الخدمة. احفظ data.id وتابع:
{"action":"status","order":"رقم_الطلب"}

احفظ المفتاح في خادمك فقط. عند فقد الرد أعد المرجع نفسه والبيانات نفسها، ولا تنشئ مرجع دفع جديدًا تلقائيًا. لا تعتبر فشل المزامنة قائمة منتجات فارغة. الأسعار والرصيد في API بالدولار والإجمالي النهائي من الخادم.
