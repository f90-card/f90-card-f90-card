# ربط تلجرام لتنبيهات F90 CARD المهمة

هذه الصفحة توضح كيفية توصيل بوت تلجرام **من Supabase فقط**. لا تحفظ bot token أو Chat ID أو مفتاح عامل الإرسال داخل ملفات GitHub أو إعدادات الموقع العامة أو رسائل الدعم.

## التنبيهات التي جهزناها

- **كل طلب إيداع جديد**؛ المبلغ والعملة والطريقة ورقم الطلب، دون إيصالات أو بيانات حساسة.
- **طلبات توثيق الهوية الجديدة**؛ رقم الطلب والوقت فقط، دون صور الوثائق.
- **طلبات الاعتراض والإلغاء**؛ رقم الطلب ونوعه.
- **رسالة اختبار من صفحة المدير**؛ للتأكد من عمل الربط.

**لا تُرسل إشعارات عن كل شراء عادي.** يمكن تشغيل أو إيقاف كل فئة من: لوحة الإدارة ← تنبيهات تلجرام.

## 1. إنشاء البوت

افتح Telegram وادخل إلى **@BotFather** الرسمي، ثم استخدم `/newbot`. اختر اسمًا واسم مستخدم للبوت. احتفظ برمز API (bot token) في مكان سري. لن تحتاج إلى إرساله لأي أحد في الدردشة.

افتح محادثة البوت الجديد واضغط **Start** أو أرسل `/start`. إذا أردت إرسال التنبيهات إلى مجموعة إدارية، أضف البوت إلى المجموعة.

## 2. العثور على معرّف المحادثة (Chat ID)

يختلف معرّف المحادثة الخاصة عن معرّف المجموعة (عادة تكون أرقام المجموعات سالبة). بعد إرسال رسالة للبوت، استرجع تحديثات البوت عبر واجهة Telegram الرسمية `getUpdates` من جهاز أو أداة خاصة وآمنة، واستخرج قيمة `message.chat.id`. لا تعرض رابطًا يحتوي على توكن البوت، ولا تنشر ردود `getUpdates` لأنها قد تحتوي على بيانات مستخدمين.

## 3. إعداد Supabase Edge Function Secrets

من مشروع Supabase `xzqnrpycjxfbyrfaolud` افتح **Edge Functions → Secrets** وأضف هذه الأسماء مع قيمها الحقيقية:

| الاسم | القيمة |
|---|---|
| `F90_TELEGRAM_BOT_TOKEN` | رمز البوت من BotFather |
| `F90_TELEGRAM_CHAT_ID` | معرّف المحادثة الرقمي |
| `F90_TELEGRAM_DISPATCH_SECRET` | سر عشوائي قوي لا يقل عن 30 حرفًا |

**لا تستخدم مفتاح الـAPI للتاجر أو مفتاح ياسين كارد لأي من الحقول أعلاه.**

## 4. تخزين سر المجدول في Supabase Vault

افتح **Vault** في نفس مشروع Supabase، وأنشئ سرًا جديدًا باسم:
`f90_telegram_dispatch_secret`

قيمته **مطابقة تمامًا** لقيمة `F90_TELEGRAM_DISPATCH_SECRET` في Edge Functions Secrets. هذا يسمح لمهمة قاعدة البيانات الدورية بالاستدعاء بدون تخزين المفتاح في ملفات عامة.

## 5. اختبار الإرسال

1. افتح لوحة الإدارة ثم **تنبيهات تلجرام**.
2. اترك الإيداعات مفعّلة، واختر التوثيق والاعتراضات وفق رغبتك.
3. اضغط **وضع رسالة اختبار في قائمة تلجرام**.
4. انتظر نحو دقيقة، وافتح محادثة البوت.
5. راجع جدول السجل في صفحة المدير. يجب أن تظهر الحالة **أُرسلت**.

إذا ظهر **محاولة فاشلة** راجع إعدادات أسرار Supabase، ومعرّف المحادثة، وهل ضغطت Start داخل محادثة البوت.

## آلية العمل

- Triggers في قاعدة البيانات تنشئ طلبات إشعار عند تسجيل حدث حقيقي لأول مرة.
- تُحفظ الرسائل في `public.f90_telegram_alerts` مع مرجع فريد يمنع التكرار.
- مهمة `cron` باسم `f90-important-telegram-alerts` تحاول كل دقيقة تشغيل خدمة `f90-telegram-alerts`.
- لا تُرسل أي رسائل قبل إكمال الربط بالسر المحفوظ داخل Vault وأسرار Edge Functions.
- المحاولات الفاشلة تُعاد وفق تأخير متزايد بحد أقصى ثماني محاولات لكل إشعار.
- التوكنات، كلمات المرور، الصور الشخصية والهوية، وإيصالات التحويل لا تدخل نصوص تلجرام.

**ملاحظة:** النظام لا يستطيع ضمان وصول رسالة في حال تعطل Telegram أو نفاد محاولات الإرسال؛ لذلك يبقى سجل طلبات الإيداع داخل لوحة الإدارة هو المصدر الأساسي.
