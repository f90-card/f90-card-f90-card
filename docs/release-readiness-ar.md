# F90 Card | تقرير الجاهزية للإطلاق

آخر مراجعة: 13 أكتوبر 2026. هذا المستند يميّز بين الكود الموجود وبين الإثبات العملي، ولا يعلن جاهزية تجارية لم تُختبر.

## نتائج مثبتة

- خادم Supabase Edge Function باسم `f90-platform` منشور، الإصدار 15 عند كتابة التقرير.
- استيراد أوميغا معطّل من الخادم حتى التحقق من تطابق حقوله وأسعاره؛ القراءة والفحص فقط.
- شراء وإيداع المحفظة يمران بدوال قاعدة بيانات؛ توجد قيود فريدة على `(user_id, idempotency_key)` لكل من الطلبات والإيداعات، وعلى مفتاح دفتر الحركة.
- فحص قاعدة البيانات للقراءة فقط في `docs/production-integrity-audit.sql` أعطى 0 في ستة مؤشرات: الأرصدة السالبة، تكرار مراجع الطلبات، تكرار مراجع الإيداع، مبالغ الإيداع غير الصالحة، إجمالي الطلبات السالب، وروابط المورّدين اليتيمة.
- توجد اختبارات برمجية لحالات انقطاع الاتصال والجلسة وبعض الحواجز الثابتة في API. نجاحها على CI غير مثبت بهذا التقرير.

## أمور غير مكتملة أو غير مثبتة

1. **اختبارات التزامن:** إنشاء طلبين بالمرجع نفسه في نفس اللحظة، واسترداد النتيجة بعد فشل الاتصال، وتعارض مرجع مع بيانات مختلفة. يجب إجراؤها على مشروع Supabase تجريبي مع أرصدة وهمية. لا تُنفذ على العملاء.
2. **تزامن تحديث الأسعار واستيراد دفعات الخدمات:** التحقق الحالي يمنع كثيرًا من الأخطاء، لكنه لا يضمن معاملة ذرّية للدفعة كاملة. يجب تطوير عمليات قاعدة البيانات أو آلية تعويض/استئناف مدروسة واختبارها.
3. **أوميغا والمورّدون المختلفون:** لا يجوز تفعيل الإرسال المالي إلا بعد الحصول على توثيق API رسمي واختبار حالات الحقول والكمية والعملات وحالة الطلب والاسترداد في بيئة المورّد الاختبارية.
4. **API التجار المتقدم:** Webhooks موثّقة وموقّعة، السماح بعناوين IP والتحقق منها، الصلاحيات الدقيقة، حدود الطلبات وحماية الاستدعاء.
5. **رسوم الإيداع 2%:** لم تُعتمد قاعدة مالية نهائية لها بعد. يجب حسم هل هي خصم من صافي الرصيد أم رسوم إضافية، والإفصاح عنها للعميل قبل التطبيق.
6. **VIP الشهري:** تحديد دورة الحساب الشهرية ومصدر احتساب الإنفاق، وآلية استثناء التجار واختبارها.
7. **التصاميم والصور:** اكتمال التحديثات على جميع الشاشات والهواتف، وتسليم البنرات والمنتجات كملفات منفصلة قابلة للتعديل، وإثبات عمل PWA.
8. **قبول التشغيل:** اختبار تسجيل وتوثيق وشراء وإيداع وإلغاء/استرداد والصلاحيات، وفحص قائمة أخطاء المتصفح وسجلات الخادم، وإثبات إغلاق كل الحالات الحرجة.

## شروط عدم إطلاق عمليات تلقائية بعد

- لا تمكّن مورّدًا أو مزامنة أسعار دون معاينة وتأكيد ومراجعة الأسعار.
- لا تستخدم بيانات اعتماد المورد في الواجهة أو المستودع العام، ولا تنسخ المفاتيح إلى سجل اختبار.
- لا تُجرّب أرصدة العملاء أو طلباتهم الحقيقية لإثبات النجاح.
- نجاح فحص SQL الحالي ليس شهادة بعدم وجود أخطاء مستقبلية؛ أعد الفحوصات بعد كل ترحيل قاعدة بيانات، مع مراقبة الأخطاء.
- لا تعلن اكتمال المشروع قبل إتمام عناصر القبول أعلاه وتوثيق نتائج الاختبار.
