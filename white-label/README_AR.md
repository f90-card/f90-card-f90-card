# نسخة F90 CARD القابلة للتخصيص وإعادة البيع (White Label)

هذه **نسخة أساس منفصلة عن متجر F90 CARD المباشر**. أنشئت من نسخة GitHub المؤرخة 2026-10-16؛ لا تُغيّر الفرع main.

## حدود النسخة المحفوظة
- الفرع backup/2026-10-16-full-audit يحفظ **كل الملفات المتعقبة في GitHub** عند commit 098e402bda1f8803401ad2cec25ea08af7f9c5f1، بما فيها الواجهات، التصميمات، اختبارات المشروع، ملفات Supabase البرمجية والتعديلات التاريخية.
- **لا يحتوي هذا الفرع على تصدير حيّ** من قاعدة بيانات العملاء أو صورهم الخاصة أو كلمات مرور Supabase أو أسرار مزودي الخدمات أو إعدادات استضافة Vercel غير المخزنة في المستودع.
- هذه النسخة مبدئيًا مخصصة للتخصيص والتجهيز. **ليست نسخة معتمدة للبيع فورًا**؛ يوجد شعار وهوية وأصول F90 داخل الكود والصور، ويجب استبدالها بعد تحديد هوية المشتري ومراجعة الحقوق.

## تحضير نسخة عميل منفصلة
1. احتفظ بفرع النسخة الاحتياطية ولا تعدل عليه.
2. انسخ مشروع GitHub إلى مستودع **خاص جديد** للمشتري. لا تربط العميل بمستودع F90 الإنتاجي.
3. أنشئ حساب/مشروع **Supabase جديدًا** للمشتري، بقاعدة وAuth وStorage وEdge Functions جديدة. لا تشارك قاعدة F90 ولا تكرر بيانات العملاء والأرصدة والطلبات. لا تُفعّل التحويل المالي حتى تختبر السياسات والأسعار والصلاحيات.
4. انسخ `white-label/client.example.json` إلى ملف JSON خاص بالعميل، وأدخل اسم المتجر ورابطه ووسيلة تواصله ورابط Supabase العام والمفتاح **العام** للعميل. لا تضع `service_role` أو توكن المورد أو توكن تلجرام في هذا الملف أبدًا.
5. شغّل `node scripts/create-client-store.mjs ./white-label/client.example.json ../client-store-export` من جذر نسخة القالب على حاسوبك. الملفات تُنشأ في مجلد منفصل، ولا تتغير ملفات المتجر الأصلية.
6. راجع ملف `CLIENT_REBRAND_CHECKLIST.md` الناتج. استبدل كل الشعارات/الأيقونات والصور ذات حقوق F90، ثم عيّن اسم النطاق وSEO وmanifest وصفحات الإدارة وواتساب والدعم والإيداع.
7. جهّز **مخطط قاعدة بيانات جديدًا مدقّقًا**. ملفات `supabase/migrations` التاريخية تخص بيئة F90 ولا ينبغي تطبيقها على مشروع المشتري مباشرة؛ أُزيلت من تصدير العميل لئلا تعيد إنشاء بيانات وأسعار وحسابات المالك الأصلي. اصنع clean baseline بعد مراجعة بنية الجداول ووظائف الصلاحيات.
8. أنشئ حساب مدير جديدًا، أعد إعداد 2FA ومزود البريد وTelegram وAPI الموردين وcron لكل مشترٍ على حدة؛ لا تنقل مفاتيح ف90 ولا بياناته.
9. قبل التشغيل العام: افحص عدم وجود مراجع للإنتاج، اختبر تسجيل الدخول، تسجيل الطلب، الإيداع الوهمي دون تحويل حقيقي، مراجعة الطلب دون إيداع حقيقي، المخزون/قيد التعبئة، ورفض دخول عميل إلى بيانات عميل آخر.
10. تحقق من ملكية وترخيص الشعار والخطوط والأيقونات وصور تطبيقات الجهات الخارجية وشروط API قبل البيع؛ بيع الكود لا يعني نقل حقوق أطراف أخرى تلقائيًا.

## متطلبات الأمان قبل كل عملية بيع
- بيئة/مستودع منفصلان تمامًا لكل عميل. لا تستخدم رابط أو مفتاح Supabase الإنتاجي.
- لا تنسخ قاعدة العملاء أو أرقام التواصل أو الإيصالات أو سجل المعاملات أو توكنات API.
- افحص `f90-platform` وRPC ذات `SECURITY DEFINER` وRLS، والمفاتيح العامة/الخاصة وقيود المبالغ قبل تمكين التعاملات المالية.
- أصلح التحذيرات الأمنية على قاعدة العميل أو وثق قبول المخاطر قبل تسليمه.
- اختبر إعدادات GitHub Pages / Vercel وAuth redirect وملفات manifest وSEO وWebhooks.
- جرّب النسخ على بيئة اختبار، لا على متجر F90 الفعلي.

## عناصر لم تُحوّل تلقائيًا
الأسماء الداخلية لدوال البرمجة (مثل `F90API`) وأسماء الجداول وملفات الهجرة الأصلية والرسومات الثنائية. إعادة تسميتها عشوائيًا تكسر النظام. غيّر الهوية **المرئية** والإعدادات والبنية التحتية أولًا، ثم أعد بناء النسخة بعد الاختبار.

**الحالة:** أساس محفوظ وقابل للنسخ والتخصيص، وليس متجرًا مستقلًا جاهزًا لتلقي أموال العملاء قبل إعداد مخطط قاعدة جديدة وتشغيل اختبارات الأمان.
